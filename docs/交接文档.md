## 2. 软件 GoDojo 使用手册

**启动**:双击 `F:\围棋\启动围棋.bat`(或 `pythonw.exe F:\围棋\GoDojo.py`)
启动后需 **5–10 秒**加载引擎,期间点棋盘无效。

### 界面(顶部一排 + 右侧面板)

| 控件 | 选项 | 说明 |
|---|---|---|
| **棋盘** | 9 / 13 / 19 | 切换会**自动开新局** |
| **你执** | 黑(先手)/ 白(后手) | 同上 |
| **对手** | 内置AI / 外接AI(文件) / AI对AI(双文件) | 见第 4 节 |
| **让子** | 0(分先)/2/3/4/5 子 | 让子局自动设贴目 0.5 且**白方先行** |
| **AI强度** | 20–800 滑块 | 直接下发 `kata-set-param maxVisits N` |

**按钮**:新局 / 悔棋(一次退双方各一手)/ 提示(棋盘上画 A·B·C 推荐点)/ 停一手 / 认输 / 分析 / 保存棋谱

**右侧面板**:状态提示 · 胜率条(目差换算的估算胜率)· 引擎候选点 · 对局记录 · 讲评

**棋谱**:每手自动写 `games\godogo_YYYYMMDD_HHMMSS.sgf`(**新局自动开新文件**,不会覆盖)

### 命令行参数(可直接开好设置的一局)

```powershell
pythonw "F:\围棋\GoDojo.py" --size 19 --handicap 4 --visits 800 --new
pythonw "F:\围棋\GoDojo.py" --ai-vs-ai          # 进入 AI 对 AI(双文件)模式
```

## 3. 引擎(KataGo)

| 项 | 值 |
|---|---|
| 主引擎 | `F:\围棋\KataGo-opencl\katago.exe`(OpenCL 后端) |
| 权重 | `kata1-tf3-b11c768-s11500M-d6163M.bin.gz`(tf3 架构,201.8 MB) |
| 配置 | `F:\围棋\KataGo-opencl\gtp_practice.cfg` |
| 关键参数 | `maxTime = 20`(每手最多 20 秒)· `maxVisits/maxPlayouts = 100000` · `numSearchThreads = 8` · `allowResignation = false`(永不认输) |
| 调优缓存 | `KataGoData\opencltuning\tune13_gpuIntelRArcTM130TGPU16GB_*.txt` |

**性能实测(Intel Arc 130T 集显)**
- 9 路:30 visits ≈ 2–3 秒/手;800 visits ≈ 30 秒/手
- 19 路:800 visits **> 2 分钟/手** → 所以改用 `maxTime = 20 秒` 限时(实际约 1000+ visits)

**⚠️ 多开陷阱**:重复启动软件会留下多个 `katago.exe`,互相抢 GPU 导致极慢。
启动前建议:`Get-Process katago | Stop-Process -Force`

## 4. 外接 AI 文件接口(让任意 AI 来下)

目录 `F:\围棋\外接AI\`:

| 文件 | 谁写 | 内容 |
|---|---|---|
| `position.txt` | **软件写** | 当前局面:棋盘图 + 着法历史 + 空点列表 + "轮到你/轮到白/轮到黑" |
| `ai_move.txt` | **外接AI写** | 单个坐标,如 `E5`;停一手写 `pass`(外接AI 模式) |
| `black_move.txt` / `white_move.txt` | 双方写 | AI对AI(双文件)模式使用 |
| `ai_error.txt` | 软件写 | 着法非法时的原因 |
| `协议_给外接AI.md` | — | **完整协议**(贴给 ChatGPT/Claude 当系统指令) |
| `给GPT的指令.md` | — | 简版开场指令 |
| `看局面.bat` / `出招.bat` / `白棋出招.bat` | — | 双击即用的辅助工具 |

**两种模式**
1. **外接AI(文件)**:软件执一端,外部 AI 写 `ai_move.txt`(用 `出招.bat` 输入坐标)
2. **AI对AI(双文件)**:两边都走文件 —— 黑写 `black_move.txt`,白写 `white_move.txt`

人类在软件里点棋盘是不需要文件的;外部 AI 的着法才走文件。

## 6. 踩过的坑(改代码前必读)

1. **F 盘不支持硬链接** → 写文件工具(EISDIR 报错)不可用,一律用 PowerShell `[IO.File]::WriteAllText`
2. **让子局白先行** → 回合判断必须用 `side_to_move()`,不能用"手数奇偶"
3. **打劫规则** → 必须实现"禁止全局同形再现";用简化的"单子劫"会导致引擎拒绝着法、盘面脱节
4. **引擎调用必须加锁**(`op_lock`)→ 评估线程和对局线程会抢 GTP 管道,造成死锁(现象:落子后软件"卡住")
5. **19 路高 visits 极慢** → 用 `maxTime` 限时替代固定 visits
6. **DPI 缩放** → 已加 `SetProcessDpiAwareness(2)`,否则窗口被放大、截屏错位
7. **窗口焦点** → 任何自动点击前需 `SetForegroundWindow`;窗口最小化时会截到 -32000 坐标
8. **哨兵是一次性后台任务** → 触发一次就结束,需要重新挂(或用 `turn_sentinel.ps1` 预挂一排)
9. **Sabaki 已卸载** → 曾用它做 GUI,因引擎附加/文件交互不稳,改为自研 GoDojo
10. **引擎里 `komi` 会跟着让子变** → 让子局 komi=0.5,分先 7.5
